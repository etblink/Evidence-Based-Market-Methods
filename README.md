# Evidence-Based Market Methods

A continuity-first research repository.

## Read first

1. `STATE.yaml` — the sole canonical representation of current mutable project state.
2. `GOVERNANCE.md` — the stable rules that constrain how project state may change.
3. Git history — the authoritative archive of prior project states.

No README section, issue, discussion, evidence note, experiment report, or generated view may redefine current project state.

## Repository roles

- Current conclusions, active scope, phase, and next action belong only in `STATE.yaml`.
- Evidence records what a source, dataset, or experiment supports; it does not independently define the project's current conclusion.
- GitHub issues may coordinate work but are non-authoritative.
- Historical state is recovered from Git rather than duplicated in manually maintained changelogs.
- Derived summaries, if introduced later, must be mechanically generated and non-authoritative.

The repository should remain as small as the research actually requires.
